## 3. Route I-58: noise-shaped V-cache quantization

**Idea.** When a token's value vector goes into a low-bit V cache, add the rounding error of the
previous token before rounding (first-order sigma-delta). The read path does not change, so the
attention kernel does not change. The write path needs one carry vector for each head of each
sequence.

**Why it can work (rubber duck).**
- The attention output is o = sum_i w_i v_i. With shaping, the output error is
  sum_i c_i (w_(i+1) - w_i) - w_n c_n, where c_i is the carry.
- Plain rounding error power is proportional to ||w||^2. Shaped error power is proportional to
  ||Dw||^2, where Dw is the difference of neighboring weights.
- Shaping wins when the attention weights are smooth along the token axis. It loses by about
  sqrt(2) on an isolated spike.

**What the review found.**
- FACT (reviewer's synthetic test, re-run by the main session with the same output): iid Gaussian
  V, d = 128, 2-bit, group 32, 4 sink and 64 recent tokens in FP16, 512 tokens.
  - Error ratio, shaped vs plain: diffuse weights 0.05, smooth tail 0.18.
  - Tail plus 10%, 30% and 60% of the mass on spikes: 1.20, 1.44, 1.55.
  - One more bit without shaping gives about 0.43.
- INTERPRETATION: the gain lives where the weights are smooth. The sinks and the recent window are
  the smoothest part, and they already stay in FP16. The rest is often retrieval-like and spiky.
- FACT: the baseline moved. llama.cpp merged a Hadamard rotation of the Q, K and V cache on
  2026-04-01 (PR 21038). Compare against rotated 2-bit V, not plain per-token V.
- FACT: closest prior art (none applies error feedback to the V cache along tokens):
  - an anonymous defensive disclosure (2026-06-30) applies sigma-delta carry to FP8 attention-score
    tiles;
  - "Low-Discrepancy Dither for Quantized Recurrent State Caches" (arXiv 2609.39185, 2026-09-30)
    applies dither to recurrent-state caches;
  - SDQ-LLM (arXiv 2510.03275) applies sigma-delta to 1-bit weights;
  - HyperQuant (arXiv 2606.23406) applies subtractive dither to the KV cache.
- Two more risks: eviction, page selection (Quest-style) and speculative rollback remove tokens
  and break the error cancellation. The scale must be computed on the value plus carry, or the
  carry loop overloads.

**Narrowed route.**
1. Measure, for each head, the smoothness G = ||Dw|| / ||w|| of the attention weights on the
   quantized region. Weight each head by its output energy.
2. Shape only the heads with small G.
3. New twist (from the reviewer): decode attention does not depend on the order of cached tokens
   (RoPE is already applied to K). So the scan order of the carry is free. Sort tokens by key
   similarity so that the weights are smoother along the scan.

**First decisive Mac test (about 2 days, to predeclare as E-27).**
- Qwen3-0.6B (cached locally), eager attention, CPU fp32, 4K-token texts that are already on disk.
- Step 1: dump attention, compute G per head. KILL if under 30% of the output energy sits in heads
  with G < 0.5.
- Step 2: fake-quantize real V at 2 bits with a 64-block Hadamard rotation in five conditions:
  none, shaping, gated shaping, key-sorted gated shaping, and one more bit.
- Kill criteria (reviewer's, heuristics): gated shaping gives under 1.5x lower median output error
  than rotation alone, or the perplexity gain is under 0.05 over rotated 2-bit, or needle
  accuracy falls by more than 2 points.

## 4. Routes I-59 and I-60 (weak survivors from the reviewer)

**I-59 Priority inheritance for shared-prefix producers.** A high-priority request that needs a
prefix that a low-priority request is still prefilling waits behind it. This is priority
inversion. The OS fix is priority inheritance: raise the producer's priority while a
high-priority request waits on it.
- Evidence of the pain: vLLM issue 59907 (2026-10-04) reports priority inversion during prefill
  in the priority scheduler, together with other scheduler bugs.
- Neighbors: ProServe (arXiv 2512.12928), Locality-aware Fair Scheduling (arXiv 2501.14312), a
  hotness-aware prefix KV scheduler (ACM, DOI 10.1145/3749168). I did not find an inheritance protocol.
- Test: a discrete-event simulator. Public traces have no priority tags, so the priorities are
  synthetic. KILL if the high-priority p99 TTFT improves by under 15%.

**I-60 Late binding for continuous-batching routers.** The router does not know output lengths, so
queue length misleads. Sparrow reserves slots on several workers and binds the request to the first
worker that is ready. Delay scheduling waits a short time for a worker with the cached prefix.
- Neighbors: CacheRoute (arXiv 2608.19677), DualMap (arXiv 2602.06502), llm-d "sticky until saturated"
  routing (vendor blog). I did not find late binding for LLM routers.
- Test: a simulator. KILL if the p99 TTFT gain over prefix-affine power-of-two choices is under 15%.

Both are close to the killed routing family (I-55) and use simulator evidence only.

## 5. Routes killed in R-10 (re-reviewed)

- **I-48 margin-gated monitor: KILL.**
  - FACT: DiFR (arXiv 2511.20621, 2025-11) replays a trusted reference with the same sampling seed.
    It detects 4-bit quantization with AUC above 0.999 in 300 tokens and has a vLLM integration.
  - FACT: Log Probability Tracking of LLM APIs (ICLR 2026) detects one fine-tuning step with a
    single-token logprob test, 1,000x cheaper than earlier audits.
  - FACT: the "flip invariant" that I-48 relied on is a mathematical identity (triangle inequality),
    not an experimental result (Section 8.1 row 42).
  - INTERPRETATION: a margin gate is a coarse threshold on the logit deviation. A continuous
    deviation score holds more information. This makes I-48 a heuristic, not a mechanism.
- **I-46 sampled simulation: KILL.** It is a benchmarking method (D-29). On the Mac the ground truth
  is a simulator, so the GPU-hour claim cannot be tested.
- **I-47 closed-loop validity: KILL.** A benchmarking method (D-29).
- **I-49 failure clustering: KILL as a thesis route.**
  - FACT: the Delta GPU error data (Cui et al., SC 2025) is public on Zenodo under CC BY 4.0
    (2025-08-25). R-09 was wrong about this (Section 8.1 row 43).
  - FACT: "Sparing Strategies to Minimize Reliability Impact On Large Training Jobs" (Meta, MLSys
    2026) gives closed-form spare sizing with a simulation check.
  - INTERPRETATION: the result would be a model fit, not a mechanism. An optional one-day check
    remains: fit a Hawkes model to Delta after merging same-device repeats.

## 7. Lesson

INTERPRETATION: since PagedAttention (2023), people have moved most direct OS, storage and
networking mechanisms into LLM serving and RL infrastructure. Many arrived within months in
2026. The gaps that remain sit in numerics details (I-58), or they need simulator evidence
(I-59, I-60).
