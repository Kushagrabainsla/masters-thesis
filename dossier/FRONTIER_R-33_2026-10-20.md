# 1. What changed in the world?

This section adds new facts to R-21 Section 1. R-21 facts still hold (MARS, SAGA, Crab, LMCache,
Chen and Stratton, FlashInfer-Bench, Grace power steering).

**1.1 Wide expert parallelism made one GPU a single point of failure.**
- FACT. EEP (2605.10670, May 2026): one failed rank stops a wide-EP instance with fixed
  membership. EEP restores 95% of pre-fault throughput in 52 s. A full-restart baseline stays
  down until 348 s. Steady-state cost is within 4.4% of DeepEP.
- FACT. SGLang Elastic EP (LMSYS, 2026-03), vLLM Elastic EP (2026-05) and Ray Serve LLM DP-group
  fault tolerance (Anyscale, 2026-04) ship the same direction.
- INTERPRETATION. The assumption "membership is fixed at start" is broken, and the fix ships.

**1.2 Agentic RL couples GPU rollouts with stateful sandboxes.**
- FACT. Belayer (2608.14635, 2026-07): rollout worker recovery up to 42x faster than a cold
  engine start; environment recovery 1.5x to 3.5x faster than baselines. It keeps container
  state consistent with the LLM context.
- FACT. RobustRL (2512.22492) isolates trainer and rollout failures by role. DSec (2609.22978,
  DeepSeek) separates rollout lifetime from the trainer.
- FACT (vendor). Google GKE Agent Sandbox reports time-to-first-command cut from 45 to 85 s to
  1 to 9 s for RL sandboxes. Treat as vendor numbers.

**1.3 Process-level GPU checkpoint/restore moved into vendor products.**
- FACT. NVIDIA Dynamo Snapshot (blog, 2026-05-27): releasing the KV cache cut a Qwen3-0.6B
  checkpoint on B200 from about 190 GiB to about 6 GiB. GPU Memory Service moves weights out of
  the CRIU image (gpt-oss-120B: CRIU image 129 GiB to 6.7 GiB). Single GPU only in that release.
- FACT. NVIDIA nvcf issue 1183 (2026-08-25): multi-GPU CRIU works on 8x H100 only with all
  cross-GPU transports off. Llama-3.1-70B TP=4: 9 min 56 s checkpoint, 290 GB, 2 min 2 s restore.
  SGLang hangs at capture.
- FACT. NVIDIA nvcf issue 2299 and PR 2300 (2026-10-06, open): a preload library releases
  imported mappings (NCCL P2P, CUDA IPC, NVLS) before the lock and re-creates them at the same
  virtual addresses. On 4x GB300, vLLM TP=4, 72B: first token after cross-node restore under
  90 s, versus about 340 s cold start.
- FACT. GCR (FAST 2026): 72.1% lower checkpoint latency than cuda-checkpoint.
- INTERPRETATION. Multi-GPU transparent C/R is now an NVIDIA engineering backlog item, not an
  open research question.

**1.4 Remote KV failure handling is being fixed upstream, fast.**
- FACT. vLLM v0.17.0 changed the default `kv_load_failure_policy` from `recompute` to `fail`.
- FACT. vLLM PR 53298 (open, updated 2026-10-16) says it fixes issue 49250. It restores request
  state, orders repair of shared KV blocks, blocks new prefix-cache hits on invalid blocks, and
  transfers repair ownership when an owner leaves.
- FACT. vLLM PR 62282 (merged 2026-10-20) fixes a multi-peer KV write-after-free on the Mooncake
  path. PR 61578 adds KV checksums for P/D transfers.

**1.5 Local multi-node inference became possible on Apple silicon.**
- FACT. macOS 26.2 supports RDMA over Thunderbolt 5. EXO claims 1.8x on 2 and 3.2x on 4 Macs
  (vendor). SiliconBench (2609.19169) measured 1.30x to 1.37x on two M4 Pro Mac minis.
- FACT. The user has one M4 MacBook Air. It has Thunderbolt 4, not Thunderbolt 5.

**1.6 Kernel-contract vocabulary now exists in public.**
- FACT. "Training-Inference Kernel Contracts" (2606.07581, 2026-05-26) defines contracts with
  numerical, statistical, runtime and observability clauses, and an escalation policy that maps
  violations to routing actions. It reports no production-scale evaluation. It does not mention
  FP8, NVFP4, MoE, Hopper or Blackwell.

# 3. Ideas killed by prior work

## 3.1 I-133 Elastic membership for wide-EP serving
- Exact-work attack: EEP repairs only invalidated state, restores expert coverage, and avoids
  CUDA-graph recapture on healthy ranks.
- Scoop attack: SGLang, vLLM and Ray ship elastic EP. Mooncake EP gives fault-tolerant dispatch.
- Verdict: KILL. Reopen only with a failure class that EEP does not cover (for example a slow
  rank, not a dead rank), plus a trace.

## 3.2 I-134 Context-aligned environment recovery for agentic RL
- Exact-work attack: Belayer checkpoints container file system and runtime state and keeps it
  consistent with the LLM context. It schedules checkpoints in inference gaps.
- Different-name attack: DSec keeps rollout state in sandbox and worker containers.
- Verdict: KILL.

## 3.3 I-135 Multi-GPU transparent C/R with fast transports on
- This is the closest match to the user's background. It is also the strongest kill.
- Exact-work attack: NVIDIA nvcf issue 2299 and PR 2300 release and re-create imported mappings
  at the same virtual addresses. They run quiesce, release, parallel checkpoint, restore, remap,
  resume across all processes.
- Adjacent attack: Singularity (2022) used a device proxy and a distributed barrier before
  collectives. CRIUgpu is upstream in CRIU 4.0. GCR (FAST 2026) makes C/R faster.
- Residual: SGLang capture hangs; TP=8 and cross-node are untested. These are bugs and test gaps.
- Verdict: KILL. The vendor is building the exact mechanism now.

## 3.4 I-136 Semantics-aware GPU snapshots for inference engines
- Exact-work attack: Dynamo Snapshot releases KV before capture. GMS stores weights outside
  the CRIU image. Dynamo issue 16357 (2026-10-13) tracks engine-by-engine gaps.
- Verdict: KILL. Engineering, shipping.

## 3.5 I-137 Cross-vendor KV portability
- Exact-work attack: "HBM Is Not All You Need" (2606.29986) does cross-vendor P/D with KV format
  and precision conversion and layer-wise overlap.
- Verdict: KILL.

## 3.6 I-138 Rate-limit-aware scheduling for agent fleets
- Baseline attack: gateways already enforce token budgets with admission estimates. Output-length
  prediction for scheduling is crowded (I-85 area).
- Relevance attack: the gain depends on undocumented provider accounting. The result would not
  generalize and needs paid API traffic to measure.
- Verdict: KILL as research. It may be a product feature.

## 3.7 I-139 Local TB5 RDMA Mac clusters
- Feasibility attack: needs two or more Thunderbolt 5 Macs. The user has one Thunderbolt 4 laptop.
- Exact-work attack: EXO and Apple MLX with JACCL ship tensor parallelism over RDMA.
- Verdict: KILL.

## 3.8 I-140 Reward verification as the RL straggler
- Evidence: SandMLE reports about 196 s per code execution on MLE-bench. No source measures the
  verification share of RL step time.
- Exact-work attack: async RL frameworks overlap reward with generation. GKE and DSec attack
  sandbox start time.
- Verdict: KILL as a mechanism. A measurement alone is a benchmarking paper (D-29).

## 3.9 I-120 Atomic runtime activation for remote KV recovery (re-check)
- R-21 gap: "no implemented runtime protocol that makes shared-block activation atomic with
  request liveness, ownership, and scheduler admission."
- Exact-work attack: vLLM PR 53298 orders repair of shared blocks, blocks prefix hits on invalid
  blocks, and transfers repair ownership. It has CPU tests (497 cases) and GB200 and GH200 runs.
- Adjacent: PR 62282 (merged) waits for all peers before failed receives complete. PR 57529 adds
  a failure ledger. PR 61578 adds checksums.
- Kill rule from R-21: "current main passes the matrix". Main does not pass yet, but the open PR
  claims the same scope. INTERPRETATION: when it merges, the matrix will pass.
- Verdict: KILL as research. Same lesson as R-18: issues produce fixes, not gaps.
- What would reopen it: PR 53298 closes unmerged, and a fault class outside its claims (async
  loads with hybrid state, for example) still gives wrong output on main.

# 4. Surviving ideas

No new idea survived R-33. The survivors are older ideas. I list them so the ranking is complete.

## 4.1 I-23 SafeDispatch (narrowed)

**Secret.** The fastest kernel that passes a tensor tolerance is not always the fastest kernel
that keeps model outputs unchanged.

**Problem.** Autotuners rank valid kernels by latency. A fixed tolerance can accept a
substitution that flips greedy tokens.

**Evidence.** FACT: Integer Alibi found 0/8 to 0/64 sequence agreement between CUTLASS and
Triton INT8 in vLLM on sm_89. FACT: 2609.25624 shows kernel choice differs per architecture and
flips tokens. FACT: vLLM issues 55238 and 55649 report greedy-output changes on Blackwell.

**Closest prior work.** FlashInfer-Bench, FlashInfer v0.7, Integer Alibi, MarginGate,
2609.25624 (ReproFuse), 2606.07581 (kernel contracts), vLLM batch-invariant stack.

**What prior work already solves.** Correctness-gated kernel substitution, persistent autotuning
by shape and mode, deterministic kernels, margin-triggered verification, and now a contract
vocabulary with routing actions.

**Exact remaining question.** On Hopper block-scaled FP8 and fused MoE, does the fastest
contract-safe backend change across regimes enough to beat a per-shape allow-list?

**Research question.** Can an output-aware qualification rule give at least 5% end-to-end
throughput over the best static safe policy on two models, with zero held-out contract
violations?

**Hypothesis.** MoE routing skew and CUDA-graph mode change the safe winner.

**Strongest baseline.** FlashInfer autotuning with its reference checks plus a per-shape
output-qualified allow-list.

**Cheapest experiment.** Test A (Section 7) on one H100.

**Kill condition.** Oracle gain under 2% on every model and unsafe fraction under 2%. Or the
allow-list captures at least 95% of oracle gain.

**Biggest novelty threat.** FlashInfer-Bench (substitution with checks). New: 2606.07581 owns
the "kernel contract" framing. Do not claim the contract concept; claim only measured gain and
the selection rule.

**Publication potential.** MEDIUM if the oracle passes on two models. LOW otherwise. PIVOT to a
measurement result is allowed by the predeclared rule, but D-29 ranks it low.

**Product opportunity.** A release gate for generated and experimental kernels, with
reproducible qualification evidence for inference operators.

**Confidence that the public gap exists.** LOW to MEDIUM.

# 7. Exact first experiment

Test A for I-23. The full design is in R-21 Section 7 and journal Section 5.8. R-33 changes
three items.

**Inputs.** One dense 7B to 9B FP8 model and one MoE model that fits one H100 in FP8. 200 prompts
from a public instruction set, 40% held out. Synthetic controls: zeros, outliers, scale
boundaries, routing skew. Pin vLLM, FlashInfer, CUDA, driver, model revisions and container
digest.

**Workload.** Prefill and decode separately. Batch 1, 2, 4, 8, 16, 32. Prompt buckets 128, 512,
2,048, 8,192. Eager and CUDA Graph. Real and controlled expert histograms. Greedy decoding.

**Independent variables.** Backend, layer family, precision and scale rule, batch, length,
phase, routing skew, graph mode.

**Dependent variables.** Median and p95 kernel latency. End-to-end tokens/s, TTFT, TPOT. Peak
memory. Max absolute, relative and ULP error. Logit KL, top-1 changes. First greedy divergence
position. Contract pass or fail. Policy overhead.

**Baselines.** (1) Fastest kernel, no checks. (2) Best single backend safe on all training cells.
(3) Fixed deterministic kernels (2609.25624 where available). (4) FlashInfer autotune with
reference checks. (5) Per-shape output-qualified allow-list. (6) Offline fastest-safe oracle.

**Procedure.**
1. Reproduce one known divergence. Stop if the harness cannot see it.
2. Enumerate the backend matrix from the pinned runtime.
3. Capture real layer inputs without dtype or layout change.
4. Run each candidate against one fixed reference.
5. Record tensor, logit, sequence, speed and memory results.
6. Build the allow-list on the 60% training prompts.
7. Compute the oracle on the 40% held-out prompts.
8. Test simple rules only (phase, shape, scale statistics, routing skew). Fit no learned model.
9. Bootstrap by prompt. Repeat timing at least 30 times.
10. Run the chosen rules inside vLLM under open-loop and closed-loop load.
11. Apply the frozen decision script.

**R-33 changes.**
1. Add 2606.07581 to the "do not claim" list. State the contract as a test definition only.
2. Add baseline (3) with 2609.25624 kernels where they run on Hopper.
3. Before the paid run: a Sonnet pre-run review of the cell list and kill rules (D-29), and a
   cost cap in writing. The Mac pilot (E-23) already validated the harness core.

**Output files.** `configs/cells.yaml`, `manifests/runs.jsonl`, `results/operator.parquet`,
`results/sequence.parquet`, `results/policy.parquet`, `results/decision.txt`.

**Expected plots.** Speed and divergence Pareto frontier by regime. Backend winners across phase,
batch, length and skew. Oracle gain over the allow-list. Unsafe rate against tensor tolerance.
End-to-end gain after policy overhead.

**Interpretation.** A changing winner matters only if a held-out simple rule captures it.

**GO / PIVOT / KILL (project heuristics, unchanged from R-21).**
- GO: at least 5% oracle gain on two models, and a simple held-out rule beats the allow-list by
  at least 2% with zero contract violations.
- PIVOT: oracle gain under 5%, but at least 10% of default substitutions violate the contract.
- KILL: gain under 2% on every model and unsafe fraction under 2%.
- KILL: FlashInfer checks plus the allow-list capture at least 95% of oracle gain.

**Compute.** No GPU: manifests, analysis code, decision script. One H100: full Hopper gate.
One B200: NVFP4 only after Hopper passes. No multi-GPU or cluster for the first claim.
