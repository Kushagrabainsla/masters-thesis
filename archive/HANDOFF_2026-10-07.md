## 2. Rules that apply to all work

- Write all content in ASD-STE100 (Simplified Technical English): short sentences, active voice,
  one topic for each sentence, no em dashes (D-27).
- Prefer PagedAttention-style ideas: take a proven algorithm from another field, run it in a new
  environment, change it a little if necessary, and show a visible gain. Do not make a benchmarking
  paper the contribution (D-29).
- For every experiment (D-29):
  1. Rubber duck before the run: explain each step, the expected result and what can make it
     wrong. Write the pass and kill rules into the journal (Section 6.1) before any run.
  2. Have a different model review the plan and the code adversarially before the run (use the
     Agent tool with `model: sonnet`). Fix the findings and log them as amendments.
  3. Run. Then rubber duck the results step by step.
  4. Have a different model review the results adversarially. Record the review as an R-nn entry.
- Measure the premise on real data first. It often takes minutes and can kill an idea early (lesson
  of E-27).
- Never delete journal history. Corrections go to Section 8.1. An AI recommendation is not a decision;
  log who decided in Section 10.
- After any research work, update the journal by Section 0.6 and rewrite Section 1 at the end of the
  session.

## 4. Decision waiting for the user (D-32)

Ask the user which option to run, unless the prompt already says it.

**Option 1: review I-80, then a simulator premise check.**
- I-80 idea: a load spike fills the server. The server evicts prefix caches. Agents time out and
  retry, and each retry must recompute a long prefix. The extra work can keep the server overloaded
  after the spike ends (a metastable failure, OSDI 2022). Borrowed fix: retry budgets and load
  shedding, changed to keep the caches of admitted sessions warm and to shed new or evicted sessions
  first.
- Closest prior work: CONCUR (arXiv 2601.22705, batch only, no retries), ThunderAgent (2602.13692),
  RR-Evict (2609.32278), FailureAtlas (2607.17525). Details: journal Section 5.15.
- Steps:
  1. Have Sonnet review I-80 adversarially (prior art and first principles), as in R-10.
  2. If it survives, predeclare E-28 in the journal: a discrete-event simulator of one serving replica
     with a prefix cache, prefill and decode costs, and agent sessions with tool and think gaps.
     Clients use realistic timeouts and retries (for example 2 retries with exponential backoff).
     Inject a short load spike. Measure goodput before, during and after the spike.
  3. Kill rule to propose: KILL if no realistic parameter set gives a collapse that lasts after the
     spike ends.
  4. Session timing can come from the Exgentic traces on disk or from the user's own Claude Code
     transcripts (E-24). The TraceLab public release (101 MB) is not downloaded; ask before you
     download it.

**Option 2: simulator test of a backup.** I-59 (priority inheritance for shared-prefix producers) or
I-60 (late binding for continuous-batching routers). Kill rules are in journal Section 5.14.

**Option 3: wait for a GPU and run I-23 Test A** (journal Section 5.8; the Mac harness is
